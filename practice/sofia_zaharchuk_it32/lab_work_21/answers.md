## Завдання 1. Альтернативні конструктори (task1.py)

```
Sofiia Zakharchuk, IT-32
food 85.5
Expense(2026-09-22, 'transport', 30.0, '')
from csv:  14
from json: 14
same data: True
```

Ручний ввід з клавіатури (from_input), вхідні дані подані через stdin:

```
date (YYYY-MM-DD): category: amount: comment: Expense(2026-09-21, 'food', 85.5, 'lunch')
```

Об'єкти з CSV і JSON мають однакові дані (`same data: True`), кількість збігається. Метод `__init__` лише зберігає поля, а розбір рядка (`from_csv_line`), словника (`from_dict`) і введення (`from_input`) винесені в методи класу. Вони повертають `cls(...)`, тому працюватимуть і для нащадків.

## Завдання 2. Статичні методи-перевірки (task2.py)

```
Sofiia Zakharchuk, IT-32
True False
True False False

skip line 2: bad date '2026-02-30'

```

`is_valid_date` і `is_valid_amount` викликаються без створення об'єкта: `Expense.is_valid_date("2026-02-30")` повертає `False`. У `from_csv_line` і `from_dict` некоректний рядок викликає `ValueError`, а цикл завантаження перехоплює його, друкує повідомлення й пропускає рядок.

## Завдання 3. Змінна класу (task3.py)

```
Sofiia Zakharchuk, IT-32
created: 14
--- currency UAH ---
2026-09-21  coffee           45.00 UAH
2026-09-21  food             38.00 UAH
2026-09-21  transport        16.00 UAH
--- after set_currency('USD') ---
2026-09-21  coffee           45.00 USD
2026-09-21  food             38.00 USD
2026-09-21  transport        16.00 USD
class: USD | object: USD
--- after self.currency = 'EUR' on the first object, then set_currency('PLN') ---
2026-09-21  coffee           45.00 EUR
2026-09-21  food             38.00 PLN
```

`currency` і `created` є змінними класу. `set_currency` змінює `cls.currency`, тому нова валюта одразу видна всім об'єктам, адже власного атрибута `currency` вони не мають. Якщо присвоїти `expenses[0].currency = "EUR"`, у цього об'єкта з'являється власний атрибут, і `set_currency("PLN")` його вже не змінює (це типова помилка з лекції).

## Завдання 4. Поліморфізм (task4.py)

```
Sofiia Zakharchuk, IT-32
income:    3600.00
expenses:  -510.00
transfers:    0.00
balance:   3090.00
```

`Expense`, `Income` і `Transfer` не мають спільного предка, але всі мають метод `balance_change()`. Цикл викликає його для кожного об'єкта без `isinstance`: це качина типізація. Додавання нового виду операції не вимагає змін у циклі.

## Вибір виду методу

| Метод | Вид | Обґрунтування |
|---|---|---|
| `from_csv_line`, `from_dict`, `from_input` | `@classmethod` | створюють об'єкт, потрібен клас (`cls`) |
| `set_currency` | `@classmethod` | змінює атрибут класу для всіх об'єктів |
| `is_valid_date`, `is_valid_amount` | `@staticmethod` | допоміжна перевірка, не потребує ні об'єкта, ні класу |
| `balance_change`, `__str__` | метод екземпляра | працюють з даними конкретної операції |

## Контрольні запитання

1. **Поліморфізм** — здатність різних об'єктів відповідати на той самий виклик по-своєму, а код, що викликає метод, не перевіряє тип. У моїй роботі цикл викликає `balance_change()` для `Expense`, `Income` і `Transfer`: витрата повертає від'ємне число, дохід додатне, переказ 0.
2. `@classmethod` отримує першим параметром клас (`cls`) і працює з класом: альтернативні конструктори, зміна змінних класу. `@staticmethod` не отримує ні об'єкта, ні класу, це звичайна функція, що лежить у класі, бо логічно до нього належить (наприклад, перевірка дати).
3. Метод класу першим параметром отримує сам клас (за домовленістю `cls`). З `cls(...)` альтернативний конструктор створює об'єкт саме того класу, через який його викликали. Якщо написати `Expense(...)`, нащадок `RecurringExpense.from_text(...)` повернув би об'єкт батьківського класу.
4. Коли об'єкт можна створити з різних джерел (рядок CSV, словник JSON, введення з клавіатури), а в `__init__` не хочеться додавати розбір і перевірки. Кожне джерело отримує окремий метод з промовистою назвою.
5. Змінна класу зберігається в самому класі, тому зміна через `cls.currency = ...` (або `Expense.currency = ...`) одразу видна всім об'єктам, які не мають власного атрибута з таким іменем. Присвоєння через `self.currency = ...` створює атрибут лише в одного об'єкта.
