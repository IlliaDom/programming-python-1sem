Мета роботи

Навчитися виконувати HTTP-запити бібліотекою requests, передавати параметри, перевіряти статус відповіді, читати JSON і обробляти мережеві помилки та таймаути. Ознайомитися з відкритими даними НБУ та сервісом погоди Open-Meteo.

Виконання

Завдання 1. Перший запит

Програма task1.py надсилає запит до API Національного банку України, перевіряє статус, виводить Content-Type і кількість валют. За кодами USD та EUR шукає значення курсу й дату встановлення.

Завдання 2. Витрати у валюті

З файлу expenses.csv прочитано 12 записів. Сума витрат у наданому файлі: 1 975,00 грн. Програма окремими запитами НБУ отримує курси USD та EUR і ділить суму на курс кожної валюти. Дата курсів береться з відповіді API.

Завдання 3. Погода в Олиці

Для запиту використано координати 50.72272, 25.81208. Open-Meteo повертає поля current.temperature_2m і current.wind_speed_10m та одиниці виміру у current_units. Значення погоди змінюються, тому програма друкує актуальні дані під час запуску.

Завдання 4. Обробка помилок

У task2.py передбачено аргументи демонстрації. Task4.py — запуск тих самих сценаріїв. У кожному сценарії очікується повідомлення в stderr і код завершення 1.

python task4.py connection
Помилка з'єднання з API: ... (ConnectionError)
Код завершення: 1

python task4.py http
HTTP-помилка відповіді API: ... (404 Client Error)
Код завершення: 1

python task4.py timeout
Час очікування відповіді вичерпано: ... (Timeout)
Код завершення: 1

Примітка. Текст винятку залежить від мережі та системи. Це приклади формату; щоб отримати фактичні виводи, запустіть наведені команди. Для режиму connection використовується зарезервована адреса, для timeout — 0,001 секунди.

Завдання 5. Кеш відповіді

task5.py зберігає відповідь НБУ й час отримання в cache/rates.json. Якщо файлу менше години, дані читаються з нього. Після години або за відсутності кешу виконується новий HTTP-запит. У виводі зазначається джерело.

Контрольні запитання

  1. З чого складається HTTP-запит і HTTP-відповідь?
    Запит містить метод, адресу (шлях і параметри), заголовки та, за потреби, тіло. Відповідь містить статусний рядок із кодом, заголовки й, за потреби, тіло з даними.
  2. Що означають коди 200, 404 і 500?
    200 — запит успішний. 404 — ресурс не знайдено. 500 — внутрішня помилка сервера.
  3. Навіщо передавати параметри через params=?
    Requests сам коректно кодує параметри URL, включно зі спеціальними символами. Це зменшує помилки й робить код читабельнішим.
  4. Чому кожен запит повинен мати таймаут?
    Без таймауту програма може чекати без обмеження. Таймаут дозволяє вчасно перехопити помилку та завершити роботу передбачувано.
  5. Чим ConnectionError відрізняється від HTTPError?
    ConnectionError означає, що не вдалося встановити з’єднання (наприклад, немає мережі). HTTPError виникає після отримання відповіді з помилковим статусом, наприклад 404, коли викликано raise_for_status().
  6. Навіщо кешувати відповіді API і які ризики застарілого кешу?
    Кеш скорочує кількість запитів і прискорює повторні запуски. Старі дані можуть не відображати актуальний курс або стан сервісу, тому кеш має строк придатності; у цій роботі — одна година.
